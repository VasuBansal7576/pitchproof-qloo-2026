# Keep the demo available during judging

Maintain free judge access through November 6, 2026 at 10:15 IST. That obligation follows the [official rules](https://qloo.devpost.com/rules). This runbook creates no monitor or promise of vendor uptime.

## Check before entry

1. Open the published app in a fresh browser profile.
2. Confirm that the judge needs no payment details or provider credentials.
3. Complete [the current judge journey](judge-testing.md), including generation, revision, planning acceptance, and actual export checks.
4. Record the deployed version, time, outcome, and failures.
5. Inspect the existing issued-access terms for validity through judging end.
6. Record any missing Qloo allowance or access confirmation as unresolved.
7. Inspect existing provider capacity without exposing credentials.
8. Compare expected judge use with owner, Site, and vendor limits.
9. Recheck public source, run instructions, and license access.

Current v42 has no accepted new generation. Clear that blocker before describing the application as verified end to end. A recorded historical success cannot replace a working hosted demo.

## Respond to an interruption

1. Save the displayed error and time.
2. Keep the same project and browser profile.
3. Retry the saved failed operation only when its error and capacity permit.
4. Verify that completed research remains available.
5. If a review retry is offered, inspect whether it reuses a valid private draft.
6. If failure persists, report the actual stage and stop repeated requests.

Do not infer vendor reset times from application backoff. Do not create keys, accept new terms, enable billing, or remove protections as an automatic workaround. Ask the operator to resolve an access or contractual blocker within the existing authorization process. The [Qloo terms](https://www.qloo.com/legal/terms) do not guarantee continuous service.

No email is sent by this runbook. A request for written availability confirmation remains an operator action. Finalists must also preserve the appearance and preparation availability described by the [official overview](https://qloo.devpost.com/).
