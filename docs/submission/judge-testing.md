# Test PitchProof as a judge

Open the [published app](https://pitchproof-studio.zippy17.chatgpt.site) in a desktop browser. The demo does not ask judges for payment or API keys.

Current v42 research passed with 54 real Qloo records, but zero current new generations were accepted. Provider and validation failures blocked the remaining journey. These steps describe the intended current workflow and include its stop condition. Historical successful samples do not prove that this run completes.

## Keep your browser session

Keep cookies enabled and use the same browser profile. Guest projects belong to the session that created them. Another browser, cleared cookies, or a new private session does not share the previous owner's campaigns. A project URL alone does not grant access. Create your own campaign rather than expecting the team's saved campaigns to appear.

## Enter a hypothetical footwear brief

1. Create a campaign with **Product or brand name** set to `Stride 01`.
2. Set **Category** to `Running footwear`.
3. Enter this description in **What makes it worth talking about?**. `Hypothetical footwear brief. The dark mesh upper and simple silhouette are the only supplied product details. Performance, comfort, material composition, sustainability, price, and availability are unverified.`
4. Set **Target market** to `United Kingdom`.
5. Set **Campaign objective** to `Launch a new product`.
6. Enter this intended audience in **Who are we trying to move?**. `Adult city runners exploring an everyday routine. Audience interests and motivations remain hypotheses.`
7. Enter the following two lines in the required **Supplied product facts** field. The app assigns F1 and F2 in line order.

```text
A dark mesh upper.
A simple silhouette.
```

8. Set **Shared call to action** to `Explore Stride 01`.
9. Leave **Website** blank for this hypothetical case.
10. Enter this constraint. `Use original production and audio. Do not invent benefits, endorsements, customer preferences, or advertising rights.`
11. Enter Nike as the competitor reference, On as the aesthetic reference, and Patagonia as the audience affinity reference.
12. Click **Find my references**.
13. Find and confirm the exact match for each brand.
14. Click **Start cultural research**.

The fact ledger records user-supplied details. Qloo does not verify those facts. The sample button fills inputs only, so inspect its facts and CTA before starting research.

## Handle a stopped run

1. If a provider or validation error appears, record the displayed message and time.
2. Keep the campaign and browser session.
3. When a retry is appropriate, use the saved operation's **Retry research** or **Retry campaign check** action.
4. If failure persists, stop and report the exact stage. Do not describe the later steps as completed.

Completed research remains saved. A valid private draft can be reused for a review retry. Private-draft review recovery has controlled test coverage, but the current live run did not reach review. The app does not substitute sample results for failed providers.

## Review the proposals when generation succeeds

1. Inspect all three proposals for distinct propositions and executable original ads.
2. Open **Behind the idea** and inspect an exact saved observation.
3. Open **Explore the thinking & test plan**.
4. Check that every product claim follows from F1 or F2.
5. Check that every ad uses `Explore Stride 01`.
6. Check that each evidence bridge separates the provider observation, creative interpretation, relevance, and uncertainty.
7. Inspect the concept pilot. Only the declarative message may differ between arms. Check the shared assets, selected facts, duration, channel, audience, CTA, and landing page.

The server's USD 200, seven-day plan and 1,000-impression floor per arm are proposed defaults. Before any real launch, an agency must approve the budget, calculate the sample from a baseline and practical difference, and set an analysis rule. Missing inputs mean no launch and no winner.

## Test a decision and revision

1. Use **Pass** on an unsuitable proposal and save a concrete reason.
2. Use **Refine with feedback** on another proposal.
3. Enter this feedback. `Research fresh artist and movie associations. Keep quiet city mornings. Change the creative mechanism while preserving F1, F2, and the exact CTA Explore Stride 01. Use original footage and audio. Add no product benefits.`
4. Click **Create a new version**.
5. Inspect the fresh evidence and revised proposals.
6. Use **Generation history** to check that the earlier generation remains unchanged.
7. Add **Your agency notes** with production choices, missing rights, shared pilot assets, and unresolved launch decisions.
8. Save the notes.
9. Choose a direction only if it answers the brief and feedback.
10. Open **Run performance & operator review**.
11. Review the current chosen proposal and recorded limitations.
12. Select the acceptance checkbox and click **Record operator acceptance** if the proposal is suitable for further planning.

Operator acceptance is specific to the current project version. An edit requires a new review. This acceptance does not authorize spending or an ad launch.

## Export and reopen

1. Open **Export brief** and choose **Download Markdown**.
2. If the browser blocks the download, open **Your editable brief** and select the **Markdown source** text.
3. Use your normal Copy shortcut and paste into an editor.
4. Check that the selected direction, saved notes, facts, exact CTA, evidence, and pilot controls appear.
5. Open **Printable campaign brief** and inspect the browser print output.
6. Return to **All campaigns** and reopen the campaign in the same browser.

Historical export checks found an embedded-browser download restriction and an unreliable immediate clipboard read after the Copy button. Manual select-and-copy worked then.
